## 1. Introduction

This plan describes the test approach for the User Management module of a hypothetical Client-Server application. The server exposes a REST API; the client is a Web UI consuming the same backend.

## 2. Scope

### In scope
- REST API CRUD for users (list, get, create, update, delete)
- Web UI: login, logout, post-login navigation
- E2E flow: user record manipulated via API → verified via UI
- Cross-cutting: response schema stability, error contracts, basic performance smoke

### Out of scope
- Load and stress testing
- Penetration / security testing
- Mobile clients
- Localization

## 6. Approach

- **API layer first** — fastest feedback loop, runs on every commit.
- **UI layer** — covers user-visible behavior only. No business-logic assertions in UI tests.
- **E2E** — minimal smoke set; precondition data is created via API, never via UI clicking.
- **Page Object Model** for all UI tests — selectors live in pages, intent lives in tests.
- **Explicit waits only** — no `time.sleep`, no implicit waits.

## 7. Pass / fail criteria

- Suite is **green** when all `smoke`-marked tests pass.
- Build is **blocked** if any new `smoke` test fails.
- Non-smoke failures are tracked but do not block; they must be triaged within 1 business day.

## 8. Suspension & resumption criteria

- Suspend tests if the test environment is down for >30 minutes — escalate to platform team.
- Resume when smoke tests pass against the recovered environment.
